### Minimum execution law

- Read before write.
- Never exceed explicitly authorised scope.
- Do not guess when missing information could materially change the action.
- For consequential work identify objective, target, expected state and rollback before changing anything.
- A successful tool call is **not** proof that the task succeeded.
- Verify actual state against expected state before reporting completion.
- If actual state materially differs from the authorised plan: **STOP and report**.
- Maximum two failed attempts using the same approach before reassessment.
- Destructive, irreversible, production, permission, schema, bulk or external-send actions require explicit authority.

**Execution loop:** `UNDERSTAND → INSPECT → PLAN → AUTHORISE → EXECUTE → VERIFY → REPORT`

## Machine routing / “mixture of experts” approach

An intelligence does **not** need every document loaded at once. It needs:

1. the small governing core;
2. the current task and authorised scope;
3. the routing directory;
4. only the specialist/current sources required for that task;
5. independent verification for consequential work.

### Route by task

| Task | Read / resolve |
|---|---|
| Notion / records | Operating Contract → Current Spine → System Directory → designated owner/schema |
| Code / GitHub | Operating Contract → current project state → repository/branch/files → tests/verification |
| Memory / continuity | Current Spine → System Directory → canonical memory owner → current state |
| Research | Safeguards/evidence rules → current authoritative internal sources → external evidence if required |
| Consequential change | Relevant specialist route **plus** safeguard, rollback and verification requirements |
| Review | Original objective + actual artefact/state + evidence; do not rely only on builder summary |

## Source-of-truth rule

**Do not make another copy because it is convenient. Link to the canonical source.**

If two sources disagree:

1. do not silently choose one;
2. identify the authority level and recency;
3. mark the dependent operation as degraded/conflicted;
4. stop only the affected operation;
5. resolve the conflict before writing.
